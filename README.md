# Штопка

Штопка проверяет исходный код, настройки и зависимости. Проверки собираются в визуальные сценарии. В отчёте можно открыть замечание, найти строку в исходнике и посмотреть, какие данные прошли между шагами.

## Запуск

Установите Docker с Docker Compose v2. В каталоге с `compose.yml` выполните:

```sh
docker compose up -d --build --wait
```

Откройте [Штопку на localhost:8103](http://localhost:8103/#register) и зарегистрируйтесь. В личном проекте откройте **Сценарии → Запустить проверку**, выберите свои файлы или ZIP и дождитесь отчёта. Для проверки локальных файлов внешние ключи не требуются.

При первом запуске Compose создаст PostgreSQL, Redis, фоновые обработчики и случайные ключи установки. Чтобы войти как администратор, используйте логин `admin`. Пароль выдаёт команда `docker compose exec api cat /run/darning/admin/password`.

Для восстановления пароля откройте `/recover`. При настроенном SMTP письмо придёт на подтверждённый адрес. Суперадминистратор может выдать одноразовую ссылку в меню профиля **Управление пользователями**.

Для CI/CD сохраните граф с триггером GitHub или HTTP. Ключ для внешней системы выдаётся в **Проекты → Участники → Ключи CI/CD**. Передайте его в заголовке `Authorization: Bearer <ключ>`. Список проектов доступен по `GET /api/ci/projects`. Для запуска вызовите `POST /api/ci/projects/{project}/scenarios/{scenario}/runs` с заголовком `Idempotency-Key` и JSON-полями `repository` (`@bound:<bindingId>`) и `revision` (полный SHA). Отчёт выдаёт `GET /api/ci/projects/{project}/runs/{id}/result`.

В «Сценариях» можно добавить собственную обработку строк, проверку Regex или поиск повторных ключей JSON. Для проверки по расписанию выберите дни недели либо число месяца. Внешние интеграции подключаются отдельно. Для автоматической загрузки новостей из интернета выполните `docker compose --profile online-news up -d`.

Для остановки выполните `docker compose down`. Данные и ключи хранятся в именованных томах Docker и сохраняются при обычном перезапуске. Для другого локального порта задайте `DARNING_PORT` в файле `.env`. При размещении за HTTPS-прокси укажите в нём также `BANK_PUBLIC_URL` с внешним адресом.

Каталог проверки Maven и Gradle содержит ограниченный офлайн-снимок GitHub Advisory Database. Источники записей и условия CC BY 4.0 указаны в [каталоге зависимостей](case_data/vulnerabilities.json).
