# Штопка

Штопка проверяет исходный код, настройки и зависимости. Проверки собираются в визуальные сценарии. В отчёте можно открыть замечание, найти строку в исходнике и посмотреть, какие данные прошли между шагами.

## Запуск

Установите Docker с Docker Compose v2. Запустите команду в каталоге с `compose.yml`.

```sh
docker compose up -d --build --wait
```

Откройте [Штопку на localhost:8103](http://localhost:8103/#register) и зарегистрируйтесь. В личном проекте откройте **Сценарии → Запустить проверку**, выберите свои файлы или ZIP и дождитесь отчёта. Для проверки локальных файлов внешние ключи не требуются.

При первом запуске Compose создаст PostgreSQL, Redis, фоновые обработчики и случайные ключи установки. Чтобы войти как администратор, используйте логин `admin`. Пароль выдаёт команда `docker compose exec api cat /run/darning/admin/password`.

Для восстановления пароля откройте `/recover`. При настроенном SMTP письмо придёт на подтверждённый адрес. Суперадминистратор может выдать одноразовую ссылку в меню профиля **Управление пользователями**.

Для CI/CD выберите триггер GitHub или HTTP и включите сценарий на холсте. Раздел **Сценарии → Активные сценарии** показывает ожидание событий и расписаний, очередь и выполняющиеся проверки. Кнопка «На паузу» прекращает приём новых событий.

Ключ для внешней системы выдаётся в **Проекты → Участники → Ключи CI/CD**. Передайте его в заголовке `Authorization: Bearer <ключ>`. Список проектов доступен по `GET /api/ci/projects`. Для запуска вызовите `POST /api/ci/projects/{project}/scenarios/{scenario}/runs` с заголовком `Idempotency-Key` и JSON-полями `repository` (`@bound:<bindingId>`) и `revision` (полный SHA). Отчёт выдаёт `GET /api/ci/projects/{project}/runs/{id}/result`.

В «Сценариях» можно добавить собственную обработку строк, проверку Regex или поиск повторных ключей JSON. Для проверки по расписанию выберите дни недели либо число месяца. Внешние интеграции подключаются отдельно. Для автоматической загрузки новостей из интернета выполните `docker compose --profile online-news up -d`.

Для остановки выполните `docker compose down`. Данные и ключи хранятся в именованных томах Docker и сохраняются при обычном перезапуске. Для другого локального порта задайте `DARNING_PORT` в файле `.env`. При размещении за HTTPS-прокси укажите в нём также `BANK_PUBLIC_URL` с внешним адресом.

Каталог проверки Maven и Gradle содержит ограниченный офлайн-снимок GitHub Advisory Database. Источники записей и условия CC BY 4.0 указаны в [каталоге зависимостей](case_data/vulnerabilities.json).

В **Сценарии → Библиотека** выберите «Ревью Java», «GitHub Actions и Dockerfile» или «Новые уязвимые зависимости в PR». Скопируйте процесс, укажите источник и сохраните его. Для проверки изменений зависимостей выберите привязанный репозиторий в графе с триггером PR. При запуске через HTTP-вебхук передайте также `baseRevision` с полным SHA базового коммита.

Библиотека также содержит «Безопасность Spring и JVM», «Карта маршрутов Spring» и «Ревью npm и PyPI». Последний шаблон проверяет точные версии из `package-lock.json` и `requirements.txt` по локальному справочнику. Встроены две демонстрационные записи. В разделе «Справочник уязвимостей» диалога запуска можно загрузить собственный JSON. Отчёт проверки доступен в формате SARIF.

После сохранения расписания редактор показывает время следующего запуска. В отчёте подтверждённого GitHub-репозитория можно начать сеанс исправления для одного, нескольких или всех замечаний. Каждый раунд с правками проверяется исходным сценарием в отдельной ветке. Слияние подтверждает руководитель.

Настройки почты, модели, GitHub App, Telegram и исходящего HTTP-вебхука перечислены в [.env.example](.env.example). Для локальной проверки с файлом достаточно команды запуска выше.
